# 17 - UI

> **El principio rector** (de Nate Gentile, *Cursor con Múltiples Agentes*, min 12–14): *"No se trata de una IA asistida por humanos, sino de un humano asistido por IA"*. En *OpenCode Desktop* (min 20–22) lo refuerza: el humano coordina y recibe ayuda, los agentes trabajan en paralelo. La UI no rota alrededor del editor de texto — rota alrededor de la **review queue** multi-agente.

La IA es buena para la laboriosidad repetitiva, pero **no** para el pensamiento lateral ni la creatividad: por eso nuestra UI siempre deja al humano en el centro, viendo y decidiendo.

## 2. Modo Manual vs Modo IA

### Manual
- Editor normal; los agentes quietos.
- El Context Engine provee completado + hint basado en Vector KB.
- Validation Engine corre al save igual que en IA.

### IA
- Los agentes exponen diffs vía AI Chat y Agent Console.
- Cualquier archivo editable puede bloquearse como `owned_by agentX`.
- El usuario interviene con anotaciones en línea.

## 2.2. Execution Mode selector

El ModeBar muestra los cuatro modos (`21 - Execution Modes.md`) con icono propio:

```
🕊 Manual Classic   🤝 Human-in-Loop   🛫 Autopilot   🚀 Autonomous
```

El cambio de modo dispara *downgrade seguro* (no aborta trabajo en curso, lo preserva en un checkpoint). El estado de `doom_loop` y `goal_drift` se muestran en el status bar con un icono ⚠ cuando se disparan.

## 2.3. Mission Control (referente: Cursor Desktop + OpenCode sessions)

El tab de inicio por defecto **no es el editor de código**, es **la Review Queue**:

```
┌─────────────────────────────────────────────────────────────┐
│  In Progress  (3)        │  Ready for Review (3)             │
│  ┌──────────┐ ┌─────────┐│ ┌────────────┐ ┌────────────┐     │
│  │ Build    │ │ Analyze ││ │ PyTorch    │ │ Set up     │     │
│  │ Landing  │ │ Tab vs  ││ │ MNIST      │ │ Cursor     │     │
│  │ Page     │ │ Usage   ││ │ Experiments│ │ Rules ...  │     │
│  │ 10m      │ │ 30m     ││ │ +262/-26   │ │ +58/-12    │     │
│  │ ▶ Build  │ │ ▶ Fetch ││ │ ⏸ Review   │ │ ⏸ Review   │     │
│  └──────────┘ └─────────┘│ └────────────┘ └────────────┘     │
└─────────────────────────────────────────────────────────────┘
```

- Tarjetas por agente con su fase (Reading docs / Fetching data / Generating plan / Worked for 14m 22s).
- Métricas: tiempo activo, diff `+N/-M`, archivos explorados, modelo asignado, costo acumulado.
- Botones por tarjeta: `Pause / Restart / Fork / Stop`. `Fork` crea una sesión hija `HUMAN_IN_LOOP` copiando el contexto.
- **Demos over diffs** (patrón Cursor): cada tarjeta puedo mostrar **video, screenshot, logs, URL de preview** (`http://localhost:3000`), no solo el diff textual.

## 4. Skill Picker (iluminado vs grisado)

```

★ ★ ★ ★ ★  React UI Expert    [Suggested]   ← iluminado, click ok

```

Cualquier override manual persiste y retroalimenta Learning.

## 5. Agent Console

Para ver:
- agente + rol + modelo + archivo + estado + diff actual,
- click sobre el agente → abre la ventana de su reasoning y evidencia,
- clic en una decisión → feedback ("buena/mala") que alimenta el Learning.

## 6. Acceso desde cualquier parte del mundo

Servicio web seguro (sub-dominio propio + auth SSO/OIDC) con:
- panel real-time via WS,
- listing de misiones activas,
- aprobaciones pendientes,
- chat con el agente,
- captura de terminal.

Equivalente al panel que tiene Hermes, pero multi-agente y con Console completo del swarm.

## 7. Temas & accesibilidad

Modos dark/light, alto contraste, soporte para screen reader (a11y). Validado por la Skill `accessibility-audit`.

## 8. Notas in-editor

Anotaciones flotantes sobre el rage de cada archivo (clic en una decision te lleva al Research Run Report).

## 9. Paneles avanzados

- Quality radar del Validation Engine.
- Confidence timeline de un reasoning.
- Cost por modelo y por mission.
- Swarm pool visualizer con locks de archivos.

## 10. Latencia Objetivo

Cualquier acción visible → <100ms end-to-end (cache local). Acciones que tocan swarm remoto → feedback inmediato de "en proceso" dentro de 250ms.

## 11. UI para humanos no programadores

Modo noob (opcional): traduce approvals / errores en lenguaje plano. Reutilizable con el `noob-mode` skill de Copilot si se quiere traer.

## 12. UX consistente

Lo hace todo a través de movimientos rápidos de teclado:
- `:c ` Mission, `:p` Plan, `:s` Skill picker, `:r` Research, `:v` Validation, `:o` Orchestrator override.
